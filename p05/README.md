1. Почему `new Array(3)` и `[3]` дают разные массивы?
Конструктор `Array` с одним числом понимает его как длину: `new Array(3)` создаёт пустой массив длиной 3 из «дыр» (`b[0]` даёт `undefined`, а `0 in b` даёт `false`, то есть индекса 0 нет). Литерал `[3]` создаёт массив из одного элемента со значением 3. Конструктор с несколькими аргументами ведёт себя иначе (`new Array(3, 4)` даёт `[3, 4]`), поэтому такая запись непоследовательна и на практике не используется. `Array.of(3)` всегда создаёт массив из аргументов, то есть `[3]`.

2. Чем поверхностная копия массива отличается от глубокой? Когда это важно?
Поверхностная копия (`[...arr]`) создаёт новый массив, но элементы в нём те же: числа и строки копируются значениями, а объекты копируются ссылками. Поэтому `cart === cartCopy` даёт `false`, а `cart[0] === cartCopy[0]` даёт `true`, и изменение `cartCopy[0].qty` видно в оригинале. Глубокая копия создаёт копии и вложенных объектов, и оригинал при её изменении не затрагивается. Это важно для массивов объектов (корзина, каталог) и особенно для состояния в React: чтобы изменить товар, не трогая оригинал, нужно скопировать и сам объект: `cartCopy[0] = { ...cart[0], qty: 5 }`.

3. Чем `map` отличается от `forEach` и от `filter`?
`map` вызывает колбэк для каждого элемента и собирает результаты в новый массив той же длины; исходный массив не меняется. `forEach` только вызывает колбэк для каждого элемента и ничего не возвращает (результат `undefined`), его используют ради действия, а не ради нового массива. `filter` тоже возвращает новый массив, но в него попадают без изменений только те элементы, для которых колбэк вернул истину, поэтому длина может быть меньше. `map` преобразует элементы, `filter` отбирает.

4. Что произойдёт, если не передать начальное значение в `reduce`?
Аккумулятором станет первый элемент массива, а колбэк начнёт работать со второго. Для чисел сумма при этом всё равно получится верной, а для массива объектов аккумулятором станет объект товара, и сумма превратится в строку вида `[object Object]…`. Поэтому начальное значение указывают всегда: `0` для суммы, `{}` для группировки.

5. Почему `[10, 9, 1, 100].sort()` сортирует числа неправильно?
Без функции сравнения `sort` превращает элементы в строки и сравнивает их посимвольно. Строка `'100'` начинается с `'1'`, поэтому она оказывается раньше `'25'` и `'9'`: получается `[1, 10, 100, 9]`. Для чисел нужна функция сравнения: `(a, b) => a - b` по возрастанию, `(a, b) => b - a` по убыванию.

6. Назовите три метода, изменяющих массив, и их неизменяющие аналоги.
`sort` → `toSorted`; `reverse` → `toReversed`; `splice` → `toSpliced`. Для `push` неизменяющий вариант это создание нового массива через spread: `[...arr, item]`. Неизменяющие методы нужны там, где состояние нельзя менять напрямую, например в React.

7. Почему строки в JavaScript неизменяемы и как у примитива могут быть методы?
Строка это примитив, а примитивы неизменяемы: присваивание `name[0] = 'К'` молча игнорируется, а все строковые методы не меняют строку, а возвращают новую (после `toUpperCase()` переменная `name` осталась прежней). Методы у примитива работают благодаря автоупаковке: при обращении `name.toUpperCase` движок на мгновение оборачивает строку во временный объект `String`, берёт метод из `String.prototype`, вызывает его и выбрасывает обёртку.

8. Что такое XSS и как его предотвратить при выводе данных через `innerHTML`?
XSS (межсайтовый скриптинг) это атака, при которой злоумышленник вставляет в данные разметку, например `<img src=x onerror="…">`, и если эти данные попадают в `innerHTML`, браузер разбирает их как HTML и выполняет код на странице у всех покупателей. Защита: не вставлять в `innerHTML` непроверенные данные, а пропускать каждое подставляемое значение через функцию экранирования `escapeHtml`, которая заменяет `&`, `<`, `>` и `"` на сущности (можно сделать это автоматически теговой шаблонной строкой `html`). Тогда браузер показывает разметку как текст. Разметку, которую написали вы сами, не экранируют, а подставленные данные экранируют всегда. В React всё, что подставлено в фигурных скобках JSX, экранируется автоматически.

9. Почему `test` с флагом `g` может давать разные ответы для одной строки?
Флаг `g` заставляет выражение запоминать позицию окончания последнего совпадения в свойстве `lastIndex` и продолжать следующий поиск с неё. После первого успешного `test('мышь')` значение `lastIndex` равно 4, и второй вызов начинает поиск с позиции 4, где строка уже закончилась, поэтому результат `false`, а `lastIndex` сбрасывается в 0. Третий вызов снова даёт `true`. Поэтому для проверки строки методом `test` флаг `g` не используют.

10. Чем жадный квантификатор отличается от ленивого?
Жадный квантификатор (`+`, `*`) захватывает как можно больше символов, а затем «отступает» ровно настолько, чтобы совпало остальное выражение. Ленивый (тот же квантификатор со знаком `?` после него: `+?`, `*?`) берёт как можно меньше и останавливается на первом подходящем месте. На строке `<b>Мышь</b> и <i>коврик</i>` выражение `/<.+>/g` находит одно совпадение на всю строку, а `/<.+?>/g` находит четыре тега: `<b>`, `</b>`, `<i>`, `</i>`.
