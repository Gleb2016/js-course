1. Что такое DOM и чем он отличается от исходного HTML-кода страницы?
DOM (Document Object Model, объектная модель документа) это дерево объектов в памяти браузера: каждый тег, текст и комментарий становится узлом с свойствами и методами. Исходный HTML это текстовый файл, из которого браузер строит это дерево. DOM можно менять скриптом, и страница перерисуется, а файл HTML останется прежним. Вкладка Elements в DevTools показывает текущее состояние DOM, а не исходный код.

2. Почему у `<ul>` с тремя `<li>` свойство `childNodes.length` больше трёх?
`childNodes` содержит все узлы, а не только элементы. Переносы строк и отступы между тегами это текстовые узлы `#text` (тип 3). Между и вокруг трёх `<li>` их четыре, поэтому узлов семь. Только элементы (тип 1) содержит `children`.

3. Чем живая коллекция отличается от статической? Какие методы возвращают какую?
Живая коллекция не хранит список элементов, а каждый раз заново смотрит в DOM, поэтому после добавления элемента её длина меняется. Статическая это снимок на момент вызова. Живую (`HTMLCollection`) возвращают `getElementsByTagName` и `getElementsByClassName`, статическую (`NodeList`) возвращает `querySelectorAll`. В задании 3 после вставки четвёртого `<li>` длина живой коллекции стала 4, а статической осталась 3. `getElementById` и `querySelector` возвращают один элемент или `null`.

4. Чем `textContent` отличается от `innerHTML`? Что такое XSS?
`textContent` читает и записывает только текст: теги в записанной строке отображаются буквально. `innerHTML` читает и записывает разметку, строка разбирается как HTML, и создаются новые элементы. XSS (межсайтовый скриптинг) это атака, когда в данные вставляют код вроде `<img src=x onerror=alert(1)>`, и при выводе через `innerHTML` браузер его выполняет. Данные пользователя вставляют только через `textContent` (или методы `append`, `prepend` со строками, они тоже вставляют текст).

5. Чем атрибут `href` отличается от свойства `href`?
Атрибут это то, что написано в HTML, и `getAttribute('href')` возвращает ровно эту строку (`#catalog`). Свойство `link.href` это поле объекта, и в нём полный адрес, который вычислил браузер (`http://…/index.html#catalog`). Методы `*Attribute` работают с текстом атрибутов и подходят и для нестандартных атрибутов.

6. Почему `append` уже вставленного элемента перемещает его, а не копирует?
Узел это один объект, и в дереве он может находиться только в одном месте. Когда его вставляют заново, браузер убирает его с прежнего места. Для копии используют `el.cloneNode(true)`.

7. Зачем нужен `DocumentFragment`?
Это лёгкий контейнер вне страницы. В него собирают много элементов, а потом вставляют одним вызовом: сам фрагмент «растворяется», в дерево попадает только его содержимое (в задании 6 `children.length` фрагмента после вставки стал 0). Браузер пересчитывает раскладку один раз, а не после каждого элемента.

8. Почему управлять оформлением лучше через `classList`, чем через `style`?
При `classList` оформление остаётся в CSS, а JavaScript только переключает состояние (`add`, `remove`, `toggle`, `contains`). Правила легко менять в одном месте, а не искать по коду. Через `style` значения записываются прямо в атрибут `style` каждого элемента и смешиваются с кодом. Класс `hidden` скрыл товар, но элемент остался в DOM, и его можно снова показать.

9. Что означает формула UI = f(state)? Какую проблему она решает?
Интерфейс это функция от состояния: всё состояние приложения лежит в одном объекте, а функция `render(state)` по нему описывает, как должна выглядеть страница. Действия только меняют состояние и вызывают `render`. Решает проблему рассинхронизации данных и интерфейса: при ручном обновлении надо помнить обо всех местах (таблица из шага 4 задания 10), и забытое место даёт ошибку. Счётчик и сумма при `render` считаются из `state.cart` заново и разойтись с корзиной не могут.

10. Почему при полной перерисовке теряется фокус и как это решает обновление по ключу? Какая аналогия у этого в React?
Полная перерисовка заменяет всю страницу, в том числе поле ввода. Фокус был у старого элемента, а нового поля с фокусом нет, поэтому остальные буквы теряются (в задании 10 из «мышь» остаётся «м»). При обновлении по ключу у каждой карточки есть ключ (`id` товара), а `Map cards` хранит соответствие ключа и элемента. `render` удаляет лишние карточки, создаёт недостающие и обновляет существующие, и только если значение изменилось. Поле поиска не заменяется, поэтому текст и фокус остаются. В React это виртуальный DOM: компонент вызывается заново при каждом изменении состояния, React сравнивает новое описание с прежним и вносит в настоящий DOM минимальные изменения. Для списков нужен атрибут `key`, с той же целью, что у нашей `Map cards`: понять, какой элемент списка какому соответствует.
